fix: "the audit sec is ALREADY PAUSED" — six refusals interpolated the KIND into a sentence

The operator hit this on a real run:

    REJECTED: the audit sec is ALREADY PAUSED at round 30. Resume it with /loopsec resume.

Two things wrong with one clause, and BOTH predate this mode:

    the audit sec        ungrammatical — the kind interpolated into an English sentence
    "sec"                a name the operator has never typed; they type /loopsec

`/goal` had the same bug all along — it produced "the audit goal is already RUNNING" — and
sec mode only made it visible, because "sec" is not even an English word.

SIX SITES, all of them `the audit ${kind}`: the start refusal, the pause refusal, the
stop refusal, the round-budget refusal, the resume refusal, and the double-stop refusal.
All now say `the /${loopCommandName(kind)} audit`:

    the /loopsec audit is ALREADY PAUSED at round 30. Resume it with /loopsec resume.
    the /goal audit is already RUNNING at round 30 — nothing to resume.

That is grammatical, it names the command the operator actually used, and it still
distinguishes two runs when there are two — which is the whole reason the kind was in
the sentence in the first place (line 388's refusal is about a DIFFERENT audit already
running).

VERIFICATION

Two tests: pausing a paused loop is refused with `/loopsec` in the message and no bare
`the audit sec`, and stopping an already-stopped loop reads as a sentence too. The
second one caught my own wrong assumption — stopping a PAUSED loop is ALLOWED (that is
how a pause is ended); it is the already-stopped one that refuses.
