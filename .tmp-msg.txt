test: the /loopSEC analysis engine does not thrash, measured over 200 rounds

The question the last commit left open: `enumerate -> analyse xN -> enumerate` — does it
GROW, or does it spin re-enumerating the same places? Reading the code cannot answer
that, so it was run for 200 rounds in three shapes.

    shape                              rounds  surface        findings  re-enumerated  stopped by
    diminishing sweeps (3,3,2,2,1,1,0)     28  13, all read          1              0  plateau
    never sweeps again                      8  0                     0              0  plateau
    constant 2 per sweep                  120  80, all read         10              0  ran to cap

IT GROWS AND IT DOES NOT THRASH. No item was ever enumerated twice, every enumerated
item was analysed, and the dry case stops on the plateau after exactly its window.

THE SHARE OF ROUNDS SPENT ENUMERATING IS 1/(k+1) FOR A SWEEP OF k ITEMS, and that is
the MODEL's rate rather than the loop's structure:

    items per sweep    rounds spent enumerating
    1                  50%
    2                  34%
    3                  25%
    10                 10%
    20                 5%

A one-item sweep is the worst case: half the model's turns go to writing work-list
entries. It still produced 12 findings over 200 rounds, so this is waste rather than
failure — but it is the operator's compute and it was worth two changes:

1. The analyze brief now says to record a new place THE MOMENT the analysis reveals it.
   Tracing one path is how you find the next one, and a place noticed but not recorded
   is a place the run never comes back to. That grows the list without spending a whole
   round on enumeration — which is the only lever there is, since the share is fixed by
   the sweep size.

2. The report shows the cost: `花在枚举上的轮次 | 10/30 (33%)`. Stated, not hidden.

The invariant pinned in the tests is ASYMMETRIC, and it has to be: `analyze` dominating
is the point — it is the work — so what is checked is that the ENUMERATION never takes
the tier. Asserting the symmetric version failed immediately on a two-item sweep
(`analyze 67%`), which is the correct reading of the data and the wrong test.

810 tests, 0 failures, tsc clean.
