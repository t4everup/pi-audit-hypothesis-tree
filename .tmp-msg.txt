fix: BLOCKED is progress — the plateau was punishing honesty

Found while verifying the starvation fix against the real Centreon run, which has
three blocked nodes with excellent reasons:

  H-0018 — 无法判定（blocked）。代码事实全部成立：ipIsAllowToConnect() 在
           trustedClientAddresses 为空时不进入白名单校验（WebSSO.php:220-222）…

That is the honest outcome of a real examination: the code facts were established
and the answer turns on something the source cannot show — a deployment config, a
live daemon, a decision made outside the repository. And under the old logic it
counted as ZERO progress.

`isVerdict` is `confirmed || rejected`, and `evaluateRound` used it for the
plateau signal, so eight consecutive honest "I cannot settle this from the source"
verdicts ended the audit claiming "the well looks dry".

WHY THIS IS A CORRECTNESS BUG, NOT A UX ONE: the model is pushed toward forcing a
`rejected` (a false negative, the branch is dropped and nobody revisits it) or a
`confirmed` (a false positive, which is the exact failure the challenge round
exists to prevent) rather than admitting the uncertainty. The plateau was
rewarding the wrong behaviour.

- New `isResolved()` = confirmed | rejected | blocked, used by `evaluateRound` for
  the round-productivity signal.
- `isVerdict` deliberately stays narrow. Everywhere else it is correct: a
  confirmed/rejected verdict still requires evidence, a blocked node still
  requires a reason, and a blocked node is still RE-TESTABLE when the data
  arrives — blocked means "not yet", not "decided". `markTesting` still accepts a
  blocked node, which is exactly right.
- The round detail now says so explicitly rather than printing a bare status.

Also fixed a test that had encoded the wrong assumption: "a round that only added
evidence is produced but not a verdict" used `blocked` as its example of a
non-verdict, which is the belief this commit removes. It uses `testing` now, and
three new tests cover the blocked cases including the eight-in-a-row scenario.

594 tests, 0 failures.
