feat: fence the call chain and the PoC, and add "does it need verification?"

Three changes to the report, all of them about a reader being able to triage it.

1. THE CALL CHAIN AND THE PoC ARE FENCED CODE BLOCKS

Materially shorter than bullet lists, the `file:line` of every step lines up in
one column so the chain scans top to bottom, and — this was a bug — a step whose
detail is multi-line code can no longer leak out of its bullet and break the
markdown around it. The PoC section had been dumping raw source inline after a
`-` for exactly that reason.

2. A FOURTH SECTION: 是否需要验证

The tier says how STRONG the evidence is. This says what to DO about it, which is
the question a reader triaging a report actually has.

  REPRODUCED      不需要 — a command was run and left re-runnable output
  STATIC          需要 — the code path was read but never triggered
  REASONING ONLY  必须先验证 — until then it is a lead, not a finding
  blocked         待条件满足 + the reason it waits on

Plus a CONCRETE next step built from the vector the auditor already recorded
rather than invented here — "对真实实例发送 <entrypoint>" with the payload, or,
with no vector, "先 read 它声称的代码位置". And if nobody has attacked it yet,
"且尚未被对抗复核攻击过".

Everything in it is DERIVED. The tool never decides whether a finding is good
enough; it only says what is still missing.

3. SIZE: 156 → 71.5 LINES PER FINDING

The bigger win was NOT the fenced blocks. Printing every anchored entry IN FULL
was the real cost — a grep probe carries its whole context window and a finding
can have half a dozen of them, so one finding ran to 156 lines. The PoC section
now shows ONE artifact (the sink, the line a reader opens first) and indexes the
rest by location; the full text is in tree.jsonl.

Measured on the real Centreon audit, 13 confirmed findings:

                        before              after
  per finding           156 lines           71.5 lines
  confirmed section     2031 lines / 95.5KB  930 lines / 48.1KB
  whole report          2152 lines / 109.5KB 1051 lines / 62.2KB

Evidence with NO location — a reasoning entry, a request — is still printed in
full: it has no other home, and it is the substance of why the auditor believes
the finding.

Also de-duplicated: the evidence section used to print the same code-slice the
PoC section had already shown, which was pure length.

9 new tests (615 total).
