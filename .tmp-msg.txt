feat: per-class exploitation ladders — the axes nobody asks about

The extension is a MECHANISM: it has an opinion about how a claim is recorded and
falsified, and none about what a PHP type-juggling bug looks like. That is
deliberate. But there is one thing it must know: the standard axes of depth for a
class. Not how to exploit anything — just the questions.

The gap, from a real scenario:

  confirmed:   the server fetches a caller-directed URL, file:// included,
               exfiltrated indirectly through the parsed result
  never asked: is the response reflected back?  (the echo channel)

AN UNASKED AXIS IS NOT A GAP IN THE REPORT — IT IS A GAP THE REPORT CANNOT SEE.
And the previous commit showed the consequence: a confirmed sink whose
preconditions nobody examined was reported as a usable finding.

- New ladders.ts: 19 curated ladders plus a generic fallback, because the absence
  of knowledge must not look like the absence of a question. Each axis is a
  QUESTION answerable by reading code, phrased so a "no" is as useful as a "yes",
  and each ladder names the one axis that decides whether the finding is worth
  anything at all (the SSRF one is the echo channel).

- It feeds the TWO moments where the model can still act:
    the pursue brief       question 3 becomes the ladder for the class
    the challenge brief    the axes are what to ATTACK — "there really is no echo
                           channel" is a checkable claim
    hypothesis_record      at confirmation, when the finding is still in hand

- The ladder does not report anything itself. Each unsettled axis is meant to
  become a GATE (Hypothesis.requires), not prose — prose is recorded, printed and
  tested by nothing, while a gate gets scheduled, confirmed or refuted, and shows
  up in the chain state.

Curated: ssrf, deserialization, command-injection, path-traversal,
arbitrary-file-read/write, file-upload, xxe, sqli, ssti, auth-bypass, idor,
privilege-escalation, info-disclosure, hardcoded-secret, open-redirect,
race-condition, rce, misconfiguration.

14 new tests, including one that asserts EVERY category gets a ladder, one that
asserts no axis is phrased as a task ("check X" invites a checklist tick), and one
that asserts the block never tells the model what to conclude — a ladder that only
made sense if the answer were "yes" would manufacture the speculation this system
exists to avoid.

660 tests, 0 failures.
