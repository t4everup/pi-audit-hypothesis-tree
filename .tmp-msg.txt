feat: /loopSEC — give an objective, dig, get a report

The operator's request: no hypothesis assertions, just a goal and the digging, but
with a report and pause/resume. Built, and driven end to end before it was
committed rather than after.

WHAT IT IS

`/sec "<objective>" [maxRounds=0] [plateau=8]`, plus status | pause | resume |
stop | next | tree | log | report | note | context. The command plumbing is the
existing `registerAuditLoopCommand(kind)` parameterised on a third kind, so pause,
resume, the operator's round budget, the plateau, the round cap, the widget and
the ledger all came for free — and those are the parts the operator asked for.

Round 1 reads the project and writes the note. Every later round digs.

WHAT IT DROPS, AND WHY THE REPORT SAYS SO FIRST

The hypothesis tree exists to make the output trustworthy, and every piece of it
is load on every round. This mode drops the load: no assertion gate, no verdict,
no verification tier, no falsification attempt, no challenge round. None of those
can exist without an assertion to attack, and a report claiming them would be
claiming discipline it does not have.

So the report LEADS with that table. Everywhere else here the non-claims go at the
foot; here the reader is about to scroll findings GROUPED BY SEVERITY, and severity
is exactly the field this mode does not check. A caveat read afterwards arrives
after the wrong impression has formed.

THE ONE RULE IT KEEPS

Every finding must carry an artifact — a `file` + `line`, or an `evidence` excerpt.
Without one it is refused, and `store.ts` drops such a finding on READ too, so a
hand-edited log cannot put a bare claim back. The bar is cheap (the model is reading
the code) and it is the whole difference between a triage report and a list of
things a model said.

BREADTH WITHOUT SEGMENTS

Hypothesis mode gets breadth from recon segments. A dig round does not generate
from a segment, so this mode uses the mechanism that was already there and measured:
what has NOT been read yet. `coverageGaps` gained an optional cited-set parameter,
the citations come from findings instead of nodes, and the dig brief hands over the
untouched subtrees — the same adaptive gap the coverage round uses.

FOUR BUGS, ALL FOUND BY RUNNING IT

1. `normalizeLoopState` had a kind whitelist (`goal`/`loop`) that did not learn
   about `sec`, so the loop was written to the log and dropped on the way back in.
   `/sec` printed "Loop started" and then every later command said "no audit loop
   in this project". EXACTLY the `Evidence.reproduces` allowlist bug from last
   week, in a different normalizer.

2. `/sec` created a scope hypothesis root, because the start path was shared. A sec
   run has no tree, so that was a node nothing reads — and it rendered as a
   one-node hypothesis tree, which reads as "this audit has a tree and it is
   empty". The root is now created for goal/loop only, and `startLoop` and
   `tickLoop` both know a sec run may legitimately have no root.

3. The journal listed `finding.round === round`, and it is written when the round
   is PREPARED — so it could never contain the round's own output. Measured: 2
   findings and five entries all saying "no finding recorded this round". It is
   cumulative now, like the hypothesis ledger.

4. `/sec status` and `/sec tree` fell through to the hypothesis renderers, so a
   healthy sec run printed "No hypothesis tree in this project" underneath it.

TWO THINGS THE TESTS GOT WRONG, WORTH RECORDING

`vendor/` is in `PROBE_SKIP_DIRS` on purpose (a dependency tree is not the audited
surface), so a fixture that expects it to appear as a coverage gap is wrong. And
`startLoop` on an already-running loop is refused, so a test that calls it a second
time to change `plateauWindow` measures nothing — the window stayed at 99 and the
test asserted a plateau that could not fire.

VERIFICATION

23 new tests in tests/sec.test.ts. They are written against the TRADE, not against
the feature: a test that only checked "it records findings" would pass on a version
that had quietly kept the assertion gate and on a version that had dropped the
artifact rule. So they pin both directions — a noun-phrase title is ACCEPTED, a
finding with no artifact is REFUSED, and the brief and the report never mention a
tier or a challenge round.

792 tests, 0 failures, tsc clean.
